# hal-service-api-finder 搜索说明精简设计

- 日期：2026-10-22
- 状态：设计已确认，待实现
- 目标文件：`hal-service-api-finder/SKILL.md`

## 1. 背景与问题

当前 `SKILL.md` 在第三章已经定义了完整的搜索纪律，但第五、六、七、十二章在具体步骤中反复书写完整 `xargs`/`grep` 命令和 scope 搜索段落。结果是：

- 同一组命令模板在多个章节重复出现；
- 读者需要在多处核对命令细节；
- skill 长度被重复内容拉长，真正需要强调的语义规则（上下文读取、候选判定、完整函数体等）反而不突出。

目标：把搜索命令集中定义一次，后续阶段只引用方法名和参数，不重复命令。

## 3. 新搜索方法定义

把第三章现有的 `### 搜索纪律（适用于所有范围分支）` 替换为以下紧凑小节。`<out>` 定义沿用第三章现有说明。

```text
### 搜索方法与纪律

所有阶段统一使用以下三种方法；后续只写方法名与参数，不再重复命令。

1. 精确字符串搜索：在 scope 内查找字面量。
   xargs -r -a "<out>/tmp/scope_files.txt" -d '\n' grep -I -H -n -F "<pattern>"
2. 正则/词边界搜索：需要正则时把 -F 换成 -E；需要词边界时加 -w。
   xargs -r -a "<out>/tmp/scope_files.txt" -d '\n' grep -I -H -n -E "<pattern>"
3. 指定文件搜索：已知文件在 scope 内时使用。
   grep -I -H -n -E "<pattern>" "<file>"

全局纪律：
- 只搜索 scope_files.txt 中的文件；scope_roots.txt 非 null 时才允许按根目录搜索（把文件清单换成 scope_roots.txt 并加 -r）。
- 禁止 grep -rn <project_dir>、rg <project_dir>、find <project_dir> -exec grep 等全仓搜索。
- grep -I 保留，跳过二进制文件；不得用 2>/dev/null 隐藏错误；退出码 1/123 表示无匹配，不是失败。
- codegraph 结果按 scope_files.txt 过滤；范围外搜索命中直接丢弃，已知范围外目标记 unresolved。
```

设计要点：

- 方法名固定为「精确字符串搜索」「正则/词边界搜索」「指定文件搜索」，后续引用必须使用这三个名称。
- 命令模板只在第三章出现一次；后续只出现方法名、`<pattern>`、`<file>` 等参数。
- 「指定文件搜索」只用于已在 scope_files.txt 内的已知文件，不替代全 scope 搜索。
- 全局纪律保留原有语义：scope 硬边界、禁止全仓搜索、`grep -I`、退出码、codegraph 过滤、范围外 `unresolved`。
